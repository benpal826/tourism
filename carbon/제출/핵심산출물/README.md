# 탄소정책 모니터링

배출권거래제(ETS)·CBAM 등 탄소 관련 기사를 매일 수집해 주제·지역별로 분류하고, 추세와 급증 키워드를 HTML 리포트로 만듭니다.
기획 내용은 `PRD.md`, 단계별 구현 프롬프트는 `PROMPTS.md`를 참고하세요.

## 폴더 구조

```
config.py              모든 설정 (검색어, 키워드, 임계값, 가중치, 알림 조건). 설정은 여기서만 수정
main.py                명령 진입점
carbon/
  db.py                SQLite 연결, 스키마, 마이그레이션 (PRAGMA user_version)
  sources/             수집기: base(Article, Source), google_news, boards(정부 게시판), eu, assembly, http(PoliteClient), registry
  pipeline.py          수집 → 중복 제거 → 태깅 → 저장, 출처 등급, 뉴스–공식 문서 연결, 후속 보도 검색
  tagging.py policy.py 주제·지역 태깅 / 정책 단계·국내 영향도 규칙
  filters.py tiers.py  무관 기사 필터 / 출처 신뢰도 등급
  linking.py           뉴스 제목 ↔ 공식 문서 연결 점수
  keywords.py weights.py agencies.py   급증 키워드 / 영향도 가중치 학습 / 기관 중요도
  llm.py               Claude 분류·요약·브리핑
  handoff.py           세션 AI: 분류·요약 재료 내보내기(ai-export) / 세션이 쓴 결과 검증·저장(ai-import)
  notify.py            이메일 알림 (조건 판정 / 메일 구성 / SMTP 발송)
  query.py             검색·내보내기 조건 조합
  analysis.py          리포트용 데이터 계산 (dict 반환, HTML 없음)
  render.py            분석 dict → HTML 문자열 (DB 접근 없음)
tests/                 pytest (모듈마다 test_*.py, 2단계 게이트는 test_gate.py)
tools/                 검수·측정 도구
docs/                  출처 조사 (source-research.md), 배출권 가격 조사 (price-research.md)
```

`render.py`는 DB와 `analysis`를 import하지 않고, `analysis.py`는 HTML을 만들지 않습니다.

## 설치와 실행

```
pip install -r requirements.txt        # 개발·테스트: requirements-dev.txt
python main.py run                     # 매일 실행: 수집 → 출처 등급 → LLM 분류 → 후속 보도 검색 → 연결 → 기관 점수 → 리포트
python main.py run --notify            #   + 알림 조건에 맞는 항목이 있으면 메일 발송 (--dry-run: 내용만 출력)
python main.py collect                 # 수집만
python main.py report                  # 리포트만 → reports/report_YYYY-MM-DD.html
python main.py search "키워드"          # 검색 (최근 20건)
python main.py export --from 2026-11-01 --to 2026-11-07 --topic CBAM --out out.csv   # CSV 내보내기
python -m pytest                       # 테스트
```

그 밖의 명령(`enrich`, `coverage`, `link`, `tiers`, `rank-agencies`, `refilter`, `reweight`, `classify`, `notify`)은 `python main.py --help`와 아래 각 절에 있습니다.

로그는 `logs/app.log`와 콘솔에 남습니다. DB는 `data/articles.db`입니다.
시각은 DB에 UTC로 저장하고, 리포트의 날짜 집계와 표시는 KST(UTC+9)입니다.

## 환경변수

비밀 값은 환경변수로만 읽습니다. 코드·설정 파일·로그·DB·채팅에 적지 마세요. 없으면 해당 기능만 건너뛰거나(LLM, 국회 API) 그 명령만 실패합니다(알림).

| 변수 | 쓰는 곳 | 없으면 |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | LLM 분류·요약 (`enrich`, `run`) | LLM 단계만 건너뜀, 키워드 태그 사용 |
| `ASSEMBLY_API_KEY` | 열린국회정보 법안 수집 | 샘플 모드 (키워드당 5건) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `NOTIFY_TO`, `NOTIFY_FROM` | 이메일 알림 (`--notify`) | `--notify` 실행이 실패로 끝남 (리포트는 생성됨). `--dry-run` 은 동작 |

## 리포트 화면

`reports/report_YYYY-MM-DD.html` 은 파일 하나에 CSS·JS 가 모두 들어 있어 인터넷 없이 브라우저로 바로 열립니다.

**구성** (위에서 아래 순서, 넓은 화면에서는 필터가 왼쪽에 고정)

1. **상단 요약:** 날짜, 기간, 기사 수, 무관 기사 제외 건수, AI 분류 건수, 그리고 **오늘의 요약**: 결론 3~5줄, 보고할 것 최대 3건(공식 문서 링크·정책 단계·국내 영향도·이유·관련 보도 수), 흐름 그림(상위 5개 주제의 7일 일별 건수). 출처는 "AI 요약"(예약 작업 세션) > "AI 브리핑"(API 키 방식) > "규칙 요약 (AI 요약 없음)" 순으로 표시합니다. AI 요약에 보고 항목이 없으면 규칙으로 고른 항목("규칙" 배지)을 보여줍니다
2. **공식 발표:** 정책 단계(확정·추진·미분류)와 국내 영향도(직접 규제·간접·참고) 배지. **확정이면서 직접 규제**인 항목은 붉은 테두리와 "확정 · 직접 규제" 배지로 가장 눈에 띄게 표시
3. **공식 기관 중요도:** 접혀 있음. 눌러서 펼침
4. **급증 키워드:** 배율 순. 키워드를 누르면 제목에 그 말이 든 기사만 남고, 다시 누르면 해제 (영문은 단어 단위로 비교)
5. **기사 분포:** 일별 기사 수 막대 차트, 주제·지역 가로 막대 (모두 숫자 라벨 표시)
6. **최근 뉴스:** 제목(새 탭), 언론사·시각, 출처 등급, 공식 확인 여부(확인되면 연결된 공식 문서 링크), 태그, AI 요약·중요도. 단체·업계 주장은 점선 테두리와 "단체 주장" 문구, 자극적 표현은 별도 배지

빈 섹션은 "해당 없음"으로 표시합니다. 뉴스 목록은 최근 60건만 담으므로 급증 키워드를 눌러도 목록에 해당 기사가 없을 수 있습니다.

**필터** (왼쪽 패널, 휴대폰에서는 위쪽 "필터"를 눌러 펼침)

| 필터 | 적용 대상 |
| --- | --- |
| 제목 검색 | 제목과 AI 요약에 포함된 말 (대소문자 무시) |
| 기간 (1·3·7일) | 리포트 생성 시각 기준 |
| 주제, AI 중요도 | 공식 발표와 뉴스 |
| 정책 단계, 국내 영향도 | 공식 발표는 자기 값, 뉴스는 **연결된 공식 문서**의 값 (연결 안 된 뉴스는 걸리지 않음) |
| 지역, 출처 등급, 공식 확인 | 뉴스만 |

- 조건은 주소 끝(`#topic=...&conf=confirmed`)에 저장되어 새로고침하거나 주소를 공유해도 유지됩니다. "필터 초기화"로 모두 해제합니다.
- 목록 위에 "N건 표시 / 전체 M건"이 나오고, 결과가 없으면 안내 문구가 나옵니다.
- 다크 모드는 운영체제 설정을 따릅니다. 인쇄하면 필터 패널은 빠지고 목록만 인쇄됩니다.
- 키보드만으로 조작할 수 있습니다 (Tab 으로 이동, 포커스는 주황색 테두리).

## 수집 출처

`config.py`의 `SOURCES`에서 켜고 끕니다. 특정 출처만 시험하려면 `python main.py collect --only official_boards`처럼 지정합니다.

| 이름 | 내용 |
| --- | --- |
| `google_news` | 구글 뉴스 RSS (뉴스 기사, 화제성 신호) |
| `official_boards` | 정부·공공기관 게시판 (기후에너지환경부, 한국환경공단, 온실가스종합정보센터, 산업통상부, 재정경제부, 외교부, 국민참여입법센터). 목록은 `config.BOARDS` |
| `eu_presscorner` | EU 집행위 보도자료 RSS 중 기후·배출권 관련 |
| `assembly_bills` | 열린국회정보 API의 의원발의 법률안 중 탄소·기후 관련 |

공식 사이트는 `robots.txt`를 확인하고 2초 간격으로 목록 첫 페이지만 읽습니다. 사이트 구조가 바뀌어 글을 찾지 못하면 로그에 경고가 남습니다.
국회 API는 인증키가 없어도 샘플 모드(키워드당 5건)로 동작하며, 키를 발급받으면 환경변수 `ASSEMBLY_API_KEY`에 넣습니다.

## 정책 단계와 국내 영향도 (공식 문서만)

공식 문서마다 두 가지를 판정해 리포트의 "공식 발표" 표에 보여줍니다. 뉴스 제목으로는 판정하지 않습니다.

- **정책 단계:** 추진(입법예고, 의견수렴, 예정, 법안 계류 등) / 확정(공포, 고시, 의결, 시행 등) / 미분류. 제목에서 문장 끝에 가까운 표지가 이깁니다. 규칙은 `config.POLICY_STAGE_RULES`.
- **국내 영향도:** 직접 규제(70점 이상) / 간접(40점 이상) / 참고. 제목의 키워드 점수로 정하고, 키워드가 없으면 미분류. 점수는 `config.IMPACT_SEEDS`. 더 구체적인 키워드가 있으면 일반 키워드는 무시됩니다(예: 영국 CBAM은 CBAM보다 낮게).
- **정렬:** 영향도 → 단계(확정 먼저) → 최신순.

| 명령 | 하는 일 |
| --- | --- |
| `python main.py reweight` | 키워드 가중치를 누적 데이터로 갱신하고 저장된 문서를 재판정합니다. DB에 쌓인 기간이 14일 미만이면 초기값만 쓰고, 변경 내역은 `reports/weight_changes.csv`에 남습니다. 주 1회 권장 |
| `python main.py classify` | 가중치는 그대로 두고 저장된 문서를 현재 규칙으로 재판정합니다. `config.py`의 규칙이나 초기값을 고친 뒤 사용 |
| `python tools/stage_review.py [건수]` | 판정 결과를 사람이 검수할 수 있게 표(`tools/stage_review.csv`)와 경계 사례로 뽑습니다. 정답을 적은 뒤 `--score`로 정확도 계산 |

## 뉴스와 공식 문서 연결

뉴스 제목은 자극적일 수 있어서 사실 판단에 쓰지 않습니다. 대신 뉴스가 어느 공식 문서를 다루는지 찾아 연결하고, 연결되면 그 문서의 정책 단계·영향도를 리포트에 보여줍니다. 연결되지 않은 뉴스는 **"공식 확인 안 됨"**으로 표시하고 정책 단계·영향도 집계에서 뺍니다. (화제성 집계에는 모든 뉴스가 쓰입니다.) 뉴스 본문은 읽지 않고 제목만 비교합니다.

- `python main.py run`은 수집 → 공식 문서 기반 뉴스 검색 → 연결 → 리포트 순서로 실행합니다. 연결만 하려면 `python main.py link`.
- **공식 문서 기반 뉴스 검색** (`python main.py coverage`): 일반 키워드 검색으로는 작은 보도자료의 후속 기사가 거의 모이지 않아서, 새 공식 문서의 제목으로 구글 뉴스를 따로 검색합니다. 최근 7일 안의 공식 문서 중 국내 영향도가 판정된(탄소 관련) 것만, 영향도 높은 문서부터, 한 번에 최대 15건까지 검색합니다. 문서 한 건당 최대 2번(처음, 48시간 뒤)만 검색하고, 공식 문서와의 점수가 40점 미만인 결과는 저장하지 않습니다. 설정은 `config.py`의 `COVERAGE_*`.
- 연결 점수가 `LINK_MIN_SCORE`(60) 이상일 때만 연결합니다. 근거는 같은 정책 용어, 같은 회차·숫자, 같은 핵심 단어, 제목 전체 유사도, 기관명 언급이고, 회차 번호가 다르면(제3차/제4차) 감점합니다. 같은 제도 이야기라는 근거만으로는 연결하지 않습니다. 기준은 `config.py`의 `LINK_*`.
- 처음 연결에 실패한 뉴스는 48시간 뒤 한 번 더 시도합니다. 공식 문서가 뉴스보다 늦게 올라올 수 있기 때문입니다.
- 기준을 고친 뒤에는 `python main.py link --relink`로 최근 7일 연결을 다시 계산합니다.
- `python tools/link_review.py [건수]`는 최근 뉴스의 연결 결과와 근접 후보를 표(`tools/link_review.csv`)로 뽑습니다. 사람 판정을 적고 `--score`로 오연결 비율을 계산합니다.

## LLM 분류·요약 (Claude)

제목(과 출처)만 보고 기사·공식 문서마다 **관련성, 주제, 지역, 한 줄 요약, 중요도**를 정하고, 하루 한 번 **오늘의 브리핑**(5문장 이내)을 만듭니다. 규칙(키워드)이 판단하지 못한 부분을 채우는 역할입니다.

**켜는 방법**

1. API 키를 환경변수로 설정합니다. 코드·설정 파일·채팅에 키를 적지 마세요. PowerShell에서 `setx ANTHROPIC_API_KEY "여기에_키"` 를 실행한 뒤 터미널을 새로 엽니다. (또는 `ant auth login`)
2. `python main.py enrich --limit 3` 으로 3건만 먼저 시험합니다. 로그에 처리 건수, 토큰, 추정 비용이 나옵니다.
3. 이상이 없으면 `python main.py enrich --limit 50` 후 `python tools/llm_review.py` 로 결과를 검수합니다.
4. 이후 `python main.py run` 이 매일 자동으로 수행합니다 (수집 → 출처 등급 → **LLM 분류** → 후속 보도 검색 → 연결 → 기관 점수 → 리포트).

인증 정보가 없으면 이 단계만 조용히 건너뛰고 나머지는 그대로 동작합니다. 그동안은 키워드 태그를 씁니다.

**무엇을 바꾸고 무엇을 바꾸지 않는가**

| 항목 | 처리 |
| --- | --- |
| 관련성 | 규칙이 **미판정**으로 둔 기사만 LLM이 정합니다. 규칙이 관련/무관으로 판정한 것은 바꾸지 않고, LLM 의견은 `llm_relevant`에 따로 남깁니다 |
| 주제·지역 | LLM이 처리한 기사는 LLM의 최종 목록을, 아니면 키워드 태그를 리포트에 씁니다 |
| 정책 단계·국내 영향도 | **공식 문서만**, 규칙이 미분류로 둔 값만 채웁니다 (`policy_source='llm'`, 규칙 재판정이 덮어쓰지 않음). **뉴스는 판정하지 않습니다** — 연결된 공식 문서의 값을 따릅니다 |
| 요약·중요도 | 제목 아래 한 줄 요약과 "AI 중요도"로 표시 |
| 브리핑 | 중요한 공식 문서(직접 규제·확정 우선)와 중요도 높은 뉴스만 재료로 씁니다. 입력에 없는 사실을 만들지 않도록 지시하고, 5문장 상한은 코드에서 보장합니다 |

**안전장치**

- 하루 호출 상한 `LLM_DAILY_LIMIT`(기본 200). 기사 1건 = 1호출이고 브리핑용 1호출을 남겨 둡니다.
- API 오류가 연속 3번 나거나 인증 오류가 나면 그 실행을 중단합니다 (호출 상한을 헛되이 쓰지 않으려고).
- 응답이 JSON 스키마에 맞지 않으면 1번 재시도하고, 그래도 틀리면 건너뜁니다. 한 기사는 3번 실패하면 더 시도하지 않습니다.
- 기사 제목은 신뢰할 수 없는 외부 데이터로 취급합니다 (제목 안의 지시문을 따르지 않도록 프롬프트에 명시, 값은 JSON으로 감싸 전달).
- 무관으로 제외된 기사, 단체·업계 주장(3등급) 기사, 30일이 지난 기사는 보내지 않습니다.

**모델과 비용** — 기본 모델은 `claude-opus-5-5`(effort `low`)입니다. `config.py`의 `LLM_MODEL`로 바꿀 수 있습니다. 아래는 기사 1건당 입력 약 1,000·출력 약 500토큰이라고 **가정한** 추정치이고, 실제 사용량은 `enrich` 로그와 `tools/llm_review.py`가 보여줍니다.

| 모델 | 기사 1건 | 하루 상한(200건) |
| --- | --- | --- |
| claude-opus-5-5 | 약 $0.014 | 약 $2.8 |
| claude-sonnet-5-5 | 약 $0.007 | 약 $1.4 |
| claude-haiku-5-5 | 약 $0.0004 | 약 $0.07 |

서버측 refusal fallback(`LLM_FALLBACKS`, beta)을 기본으로 켜 두었습니다. 요청이 거절되면 400이 날 수 있는데, 그러면 경고를 남기고 자동으로 끈 채 다시 시도합니다.

## 이메일 알림

알림 조건에 해당하는 항목이 **있을 때만** 리포트를 메일로 보냅니다. 해당 항목이 없으면 보내지 않습니다.

| 명령 | 하는 일 |
| --- | --- |
| `python main.py run --notify` | 매일 실행 + 조건에 맞는 항목이 있으면 발송 |
| `python main.py run --dry-run` | 매일 실행 + 메일 내용을 콘솔에만 출력 (발송·기록 안 함) |
| `python main.py notify [--dry-run]` | 수집 없이 리포트를 만들고 알림 조건만 확인해 발송(또는 출력) |

**알림 조건** (`config.NOTIFY_RULES`)

| 조건 | 기본값 |
| --- | --- |
| 주제 신규 | `CBAM/탄소국경`, `배출권거래제(ETS)` 주제의 신규 뉴스·공식 문서 |
| AI 중요도 | LLM 중요도 `high` 인 신규 뉴스·공식 문서 (LLM 단계가 켜져 있어야 함) |
| 급증 키워드 | 평소 대비 배율 3배 이상. 최근 2일 안에 이미 알린 키워드는 다시 알리지 않음 |

- **신규**는 마지막 발송 이후 수집된 것입니다. 첫 발송이면 최근 24시간 안에 수집된 것입니다. 발송에 실패하거나 `--dry-run`이면 기록이 남지 않으므로 다음 실행에서 다시 대상이 됩니다.
- 무관 기사, 단체·업계 주장(3등급) 기사, 발행된 지 7일이 지난 기사는 조건에 쓰지 않습니다.
- 한 기사가 여러 조건에 해당하면 각 조건 목록에 모두 보입니다.
- `NOTIFY_ATTACH = True`(기본)는 요약 본문 + 리포트 HTML 첨부, `False`는 리포트 HTML을 본문으로 보냅니다.
- 발송 기록은 DB `notify_log`에 남깁니다 (수신자 주소는 저장하지 않고 수신자 수만).

**SMTP 설정 (환경변수로만)**

| 변수 | 내용 |
| --- | --- |
| `SMTP_HOST` | SMTP 서버 (예: Gmail 은 `smtp.gmail.com`) |
| `SMTP_PORT` | 기본 587 (STARTTLS). 465 면 SSL |
| `SMTP_USER`, `SMTP_PASSWORD` | 계정. Gmail 은 일반 비밀번호가 아니라 앱 비밀번호 |
| `NOTIFY_TO` | 수신자, 쉼표 구분 |
| `NOTIFY_FROM` | 보내는 주소 (생략하면 `SMTP_USER`) |

PowerShell 에서는 `setx SMTP_PASSWORD "..."` 후 터미널을 새로 엽니다. 값은 코드·설정 파일·채팅에 적지 마세요.

## 검색·내보내기

```
python main.py search "배출권"                                   # 제목·요약에서 검색, 최근 20건
python main.py search "CBAM" --region EU --from 2026-11-01        # 조건과 함께
python main.py export --from 2026-11-01 --to 2026-11-07 --topic CBAM --region EU --out out.csv
```

- 모든 조건은 선택이고, 생략하면 조건 없이 전부 대상입니다. `--out` 을 생략하면 `reports/export_날짜_시각.csv`.
- **날짜**는 KST 기준이고 양 끝을 포함합니다 (`--to 2026-11-07` 은 11월 7일 23:59 KST 까지).
- **주제·지역**은 `config.TOPICS`·`config.REGIONS` 의 이름입니다. 일부만 써도 되며(`CBAM` → `CBAM/탄소국경`, `NDC` → `감축목표/NDC`), 여러 개에 걸리거나 없는 이름이면 가능한 값을 보여주고 멈춥니다. 리포트와 같은 기준(LLM 처리 기사는 LLM 주제, 아니면 키워드 태그)을 씁니다.
- **검색어**는 제목, RSS 요약, AI 한 줄 요약에서 대소문자 구분 없이 찾습니다. 공백도 그대로 포함해 찾습니다 (`EU ETS` 는 이 문구가 있는 기사만).
- 무관 기사(`relevant=0`)는 결과에서 뺍니다. 단체·업계 주장 기사는 "출처 등급" 열과 함께 남깁니다.
- CSV 는 **utf-8-sig**(BOM)로 저장해 Excel 에서 한글이 깨지지 않습니다. 열: 발행(KST), 구분(뉴스/공식), 제목, 언론사·기관, 링크, 주제, 지역, 출처 등급, 공식 확인, 정책 단계, 국내 영향도, AI 요약, AI 중요도. 정책 단계·영향도는 공식 문서에만 채웁니다.
- 제목이 `=`·`+`·`-`·`@` 로 시작하면 Excel 이 수식으로 실행하지 않도록 앞에 `'` 를 붙입니다.
- 조건 판정은 `carbon/query.py` 의 `matches()` 하나에 모여 있어, 3단계 화면 필터도 같은 규칙을 씁니다.

## 무관 기사 필터링

탄소 정책과 무관한 기사(시장조사 스팸, 증권 공시, 암호화폐, Brexit 등)를 **삭제하지 않고 `relevant=0`으로 표시**해 모든 집계와 목록에서 뺍니다. 제외한 건수는 리포트 맨 위에 표시됩니다.

**관련 기사를 잘못 숨기는 것이 무관 기사가 남는 것보다 나쁘다**는 원칙이라, 제목만 보고 확실한 것만 제외합니다.

| 판정 | 기준 | 집계 |
| --- | --- | --- |
| 관련 (1) | 탄소 정책 용어가 제목에 있음 (배출권, ETS, CBAM, NDC, 탄소세, carbon market, COP31 등) | 포함 |
| 무관 (0) | 시장조사 스팸·증권 공시·암호화폐 같은 명백한 패턴(`exclude_hard`, 정책 용어가 있어도 제외), 또는 정책 용어 없이 Brexit·기준금리 등(`exclude`). 공식 문서는 탄소 키워드가 하나도 없으면 무관 | 제외 |
| 미판정 (NULL) | 약한 단어(기후, 에너지, climate)만 있거나 제목에 단서가 없음. 예: `Rethinking Linking`은 탄소시장 연계 이야기일 수 있어 제외하지 않음 | 포함 (이후 LLM 단계가 판정) |

- 규칙은 `config.py`의 `RELEVANCE_RULES`. 고친 뒤 `python main.py refilter`로 저장된 기사에 다시 적용합니다. 이때 근거가 `rule:`로 시작하는 판정만 다시 계산하고, 이후 LLM·사람이 내린 판정은 덮어쓰지 않습니다.
- 온실가스종합정보센터처럼 모든 발표가 관련 있는 전문 기관의 문서는 키워드가 없어도 무관으로 단정하지 않습니다 (`SPECIALIZED_AGENCIES`).
- 판정 근거는 기사마다 `relevance_reason`에 남습니다. `python tools/filter_review.py`로 제외된 기사와 미판정 표본을 보고, `tools/filter_review.csv`에 맞음/오제외를 적은 뒤 `--score`로 오제외 비율을 계산합니다.
- 주제 태깅은 같은 단계에서 고쳤습니다. 영문 키워드를 글자 포함이 아니라 **단어 경계**로 비교해서 `Markets`가 ETS로, `Sets`·`Status`가 미국으로 잘못 태그되던 문제(태그 붙은 뉴스의 약 11%)를 없앴고, 재생에너지·탄소차액계약·COP31 등을 사전에 더했습니다. 성공 지표의 주제 태깅률은 **제외되지 않은 기사 기준**입니다.

## 급증 키워드

"평소 많이 나오는 단어"가 아니라 **"평소보다 특이하게 늘어난 말"**을 보여줍니다. (수학 과목 기사에 숫자가 많이 나오는 것은 특이한 일이 아니니까요.)

- **일반어 제외:** `config.py`에 두 종류가 있습니다. `GENERIC_TERMS`는 분야의 기본 어휘(carbon, energy, 탄소, 기후, 온실가스, 탄소중립 등)로, 단어 하나로는 제외하되 구체적인 말과 묶이면(`탄소중립 기본법`) 남깁니다. `BOILERPLATE_TERMS`는 과정·상투어(확대, 대응, 도입, 촉구, 개최, 소식 등)로, 단독으로도 묶음에서도 제외합니다.
- **두 단어 묶음:** `탄소국경조정제도 유예`처럼 이웃한 두 단어도 후보입니다. 쉼표·가운뎃점(`수원·안산`)이나 `및` 같은 말이 끼면 이어 붙이지 않습니다. 같은 기사에서 나온 단어와 묶음이 겹치면 더 구체적인 묶음만 남깁니다.
- **평소 대비 배율:** 최근 2일의 문서 빈도를 평소와 비교해 평소 기대치의 2배 이상 늘어난 것만 남깁니다. 배율 = (최근 건수 + 0.5) ÷ (평소 비율 × 최근 기사 수 + 0.5).
- **평소 빈도 비교는 DB에 14일 이상 쌓인 뒤부터:** 그 전에는 조회 기간(7일) 안의 이전 날들과 비교하고 일반어만 제외합니다. 리포트에 어느 방식인지 표시됩니다. 14일 이상이면 최근 30일을 평소로 보고, 평소에도 기사 제목의 30% 이상에 나오는 말은 뺍니다.
- 단체·업계 주장(3등급) 기사는 이 계산에 쓰지 않습니다.
- 일반어 목록은 `config.py`에서 고칩니다. 판단이 갈리는 분야 용어(ets, cbam, 재생에너지)와 국가·지역명은 일부러 넣지 않았습니다.

## 공식 기관 중요도

환경부(현 기후에너지환경부)는 **1순위로 고정**하고, 나머지 기관은 이 프로젝트에 쌓인 데이터로 0~100점을 계산해 리포트의 "공식 기관 중요도" 표와 "공식 발표" 정렬에 씁니다. 머신러닝이 아니라 아래 지표의 단순한 가중합이고, 외부 웹 검색으로 영향력을 추정하지 않습니다.

| 지표 | 가중치 | 내용 |
| --- | --- | --- |
| volume | 0.30 | 최근 90일의 탄소 관련 발표 수 (로그 스케일, 최다 기관 = 100) |
| citations | 0.30 | 그 발표를 다룬 뉴스 수 (공식 문서와 연결된 뉴스, 단체·업계 주장 제외, 최다 기관 = 100) |
| decided | 0.20 | 정책 단계가 판정된 발표 중 '확정' 비율 |
| direct | 0.20 | 탄소 관련 발표 중 '직접 규제' 비율 |

- `python main.py rank-agencies`로 계산합니다 (`run`에 포함). **DB에 14일 이상 쌓인 뒤부터** 계산하고, 그 전에는 "누적 부족"으로 표시합니다. 탄소 관련 발표가 3건 미만인 기관은 근거 부족으로 점수를 내지 않습니다.
- 지표별 값과 가중치는 `agencies.evidence`(JSON)와 `reports/agency_ranking.csv`에 남습니다.
- **한계:** 발표 수는 기관의 영향력만이 아니라 수집 설정(어떤 게시판을 필터 없이 저장하는지)도 반영하고, 정책 단계가 판정되지 않는 발표가 많으면 '확정 비율'이 낮게 나옵니다. 그래서 배출권거래제를 운영하는 온실가스종합정보센터가 외교부보다 낮게 나올 수 있습니다. 이럴 때는 `config.py`의 `AGENCY_OVERRIDES = {"온실가스종합정보센터": 85}`처럼 점수를 직접 지정합니다. 순위를 고정할 기관은 `AGENCY_FIXED`.

## 출처 신뢰도 등급

단체·업계의 주장이나 자극적으로 쓴 기사를 공식 정보와 구별해 보여주기 위한 표시입니다. 매체의 정치적 성향 같은 것은 판단하지 않고, 도메인 종류·이름 형태·수집 빈도처럼 눈으로 확인할 수 있는 사실만 근거로 씁니다. 근거는 기사마다 `source_tier_reason`에 남습니다.

| 등급 | 기준 |
| --- | --- |
| 1 공식 | 공식 출처(F7) 문서, 정부·국제기구 도메인(`go.kr`, `europa.eu`, `un.org` 등) |
| 2 일반 | 통신사·주요 언론 목록(`config.MAJOR_OUTLETS`)에 있거나, 최근 30일에 3건 이상 수집된 언론사 |
| 3 단체·업계 주장 | 협회·재단·환경단체 같은 단체 이름, 보도자료 배포 사이트(openPR, PR Newswire 등), `or.kr` 도메인. 이름에 `…뉴스`, `…신문`이 있으면 언론으로 봅니다 |
| 미분류 | 위에 해당하지 않고 수집 건수가 적어 판단할 근거가 부족 |

- **3등급은 집계에서 제외합니다.** 일별 기사 수, 주제·지역 분포, 급증 키워드를 계산할 때 빼고, 뉴스 목록에는 배지와 함께 표시합니다. 같은 사안을 공식 문서나 1·2등급 언론이 다루지 않았다면 **"단일 출처 주장"**으로 표시합니다.
- **자극적 표현**(충격, 경악, 폭로 등)이 제목에 있으면 표시만 합니다. 점수 계산이나 삭제에는 쓰지 않습니다.
- **자동으로 바꾸지 않고 "검토 필요"로만 표시하는 것:** 연구소·센터·대학·컨설팅사 같은 이름과 `.org` 도메인.
- **등급이 틀렸을 때:** `config.py`의 `SOURCE_TIER_OVERRIDES`에 `{"언론사명 또는 도메인": 등급}`을 적고 `python main.py tiers`를 실행합니다. 이름 규칙은 `ORG_NAME_PATTERNS`, 주요 언론 목록은 `MAJOR_OUTLETS`.
- `python tools/tier_review.py [건수]`로 상위 언론사의 등급·근거, 3등급 전체, 빈도만으로 2등급이 된 곳, 검토 필요 후보를 한 번에 봅니다.

## 기준선 측정

`python tools/baseline.py`는 현재 주제 태깅률과 태그 없는 기사 50건 샘플(`tools/sample_untagged.csv`)을 만듭니다.

## 매일 자동 실행 (Claude 앱 예약 작업)

매일 실행은 Claude 앱의 예약 작업 `carbon-daily`(매일 08:00)가 맡습니다. 예약 작업 세션이 `python main.py run` 으로 수집하고, 규칙이 판정하지 못한 기사의 분류와 오늘의 요약을 **세션의 Claude 가 직접** 씁니다. API 키는 필요 없고 구독 사용량을 씁니다. 프롬프트 원문은 `docs/scheduled-task-prompt.md` 에 있습니다.

```
python main.py ai-export classify     # work/ai_classify_날짜.json (하루 최대 config.SESSION_AI_MAX_ITEMS 건)
#   → 세션이 work/ai_classify_날짜.out.json 을 씀
python main.py ai-import classify     # 검증 후 저장 (규칙 판정은 덮어쓰지 않음, 형식이 틀린 항목은 실패 횟수 +1)
python main.py ai-export summary      # work/ai_summary_날짜.json (요약 재료: 중요한 공식 문서·뉴스, 급증 키워드, 주제 건수)
#   → 세션이 work/ai_summary_날짜.out.json 을 씀
python main.py ai-import summary      # 검증 후 저장: 재료에 없는 숫자가 든 결론, 근거(공식 문서) 없는 보고 항목은 버림
python main.py report
```

- 마지막 단계에서 그날 리포트를 claude.ai 고정 페이지 "탄소정책 모니터링"에 다시 올려, 휴대폰에서도 같은 링크로 볼 수 있습니다 (비공개 페이지).
- 예약 작업은 Claude 앱이 켜져 있을 때 돕니다. 정해진 시각에 앱이 꺼져 있었으면 다음에 앱을 켤 때 실행됩니다.
- 세션 방식은 `llm_usage`(API 호출 상한)에 기록하지 않습니다. 그날 세션이 분류한 건수는 `daily_summaries.classified` 에 남습니다.
- `ai-import` 는 파일이 없거나 JSON 이 깨졌거나 다른 날짜의 파일이면 종료 코드 2 로 끝나고 DB 를 바꾸지 않습니다.
- `run_daily.bat` 은 손으로 한 번에 돌릴 때 씁니다 (`python main.py run` 을 실행하고 출력을 `logs.txt` 에 덧붙임). AI 분류·요약은 하지 않습니다.
