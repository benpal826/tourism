## 3. 불합격 항목

### QA-B1 · `run_daily.bat` 없음 (NF-03) — 심각도 보통 · 1단계(저장소 이전) · **수정됨 (2026-11-13)**

- **증상:** PRD 7장과 README 는 Windows 작업 스케줄러가 `run_daily.bat` 를 실행한다고 안내하지만, 저장소에 이 파일이 없다.
- **재현:** `ls run_daily.bat` → 없음. README "매일 자동 실행" 절의 `schtasks` 명령이 없는 파일을 가리킨다.
- **추정 원인:** 이전 환경에서 압축 파일로 옮길 때 빠졌다 (압축 파일의 `2_소스코드_및_데이터` 에 없었음).
- **영향:** README 대로 예약 실행을 걸면 매일 실행이 실패한다. 코드 자체는 `python main.py run` 으로 정상 동작.
- **수정:** README 설명대로 `run_daily.bat` 을 다시 만들었다. bat 파일이 있는 폴더로 이동(`cd /d "%~dp0"`)해 `python main.py run` 을 실행하고, 실행 시각과 출력·오류를 `logs.txt` 에 덧붙이며, 실패 코드를 작업 스케줄러에 돌려준다. cmd 가 읽을 수 있게 CRLF·ASCII 로 저장하고 `.gitattributes` 로 줄바꿈을 고정했다.
- **검증:** 재현 테스트 `test_qa_b1_run_daily_bat_exists_and_matches_readme` 가 수정 전 실패, 수정 후 통과. **Windows 에서 실제 예약 실행은 검증 못 함** (이 환경은 Linux). 이전 PC 의 원본과 다를 수 있다.

### QA-B2 · 주제 태깅률 55.7% (KPI-01, 목표 85%) — 심각도 보통 · 2단계

- **증상:** 실제 수집 제목 61건(고정 DB: 뉴스 50, 공식 11)에서 주제 태그가 붙은 비율이 55.7% (뉴스 60%, 공식 4/11).
- **재현:** `tests/fixtures/sample.db` 의 실제 제목에 `tagging.tag_text` 를 적용.
- **추정 원인:** 키워드 규칙만으로는 제목이 짧거나 간접적인 기사(지자체 협약, 세미나, 기관 공지)를 분류하지 못한다. 설계상 나머지는 LLM 단계(F5)가 채우는데, API 키가 없어 한 번도 실제로 적용하지 못했다.
- **심각도를 보통으로 둔 이유:** 리포트와 필터는 정상 동작하고, 태그가 없는 기사도 목록에는 나온다. 다만 주제 필터·주제 분포가 기사의 약 절반만 반영한다. **LLM 을 쓰지 않기로 하면 이 지표를 채울 방법이 없으므로 "높음"으로 올려야 한다.**
- **수정안:** (1) API 키로 `enrich` 를 적용한 뒤 재측정 (권장), (2) 키워드 사전 보강 (효과 제한적, 오태깅 위험).
- **재측정 (2026-11-13, PC):** API 키 대신 세션 AI 분류(`ai-export`/`ai-import classify`)로 150건을 분류한 뒤, 운영 DB 의 무관 제외 기사 284건 중 250건에 주제 태그 → **88.0%** (AI 분류된 146건만 보면 91.8%). 측정 대상이 QA 때의 고정 표본 61건과 다르므로 같은 표본 재측정은 미측정.

### QA-B3 · 한국어·암호화폐 제외 패턴 누락 (F6-01) — 심각도 낮음 · 2단계(2-7) · **수정됨 (2026-11-13)**

- **증상:** README 는 "증권 공시, 암호화폐, Brexit·기준금리 등"을 무관으로 제외한다고 안내하지만, `config.RELEVANCE_RULES` 에는 영문 패턴(`crypto`, `policy rate`, `earnings call` 등)만 있다. `Bitcoin price surges…`, `한국은행 기준금리 동결`, `[공시] OO전자, 3분기 영업이익 발표` 가 무관(0)이 아니라 미판정(NULL)으로 남는다.
- **재현:** `python -m pytest tests/test_qa_offscreen.py -rx` → strict xfail 3건.
- **추정 원인:** 2-7 에서 실제 수집 데이터(영문 스팸 위주)에 맞춰 패턴을 만들었고 README 예시와 맞추지 않았다.
- **영향:** 이런 기사가 집계에 남는다. 원칙("관련 기사를 잘못 숨기는 것이 더 나쁘다")상 미판정은 안전한 쪽이며, 관련 기사를 잘못 제외한 사례는 30건 중 0건.
- **수정:** `config.py` 의 `RELEVANCE_RULES["exclude"]` 에 `기준금리`, `[공시]`, `bitcoin`, `비트코인` 을 추가했다 (코드 변경 없음). 처음 제안과 달리 모두 `exclude_hard` 가 아닌 `exclude` 에 넣어, 제목에 정책 용어가 있으면 관련으로 남게 했다 (예: 비트코인 채굴 탄소세 기사). `[공시]` 는 괄호까지 맞춰 `공시지가` 에 걸리지 않는다.
- **검증:** strict xfail 3건을 일반 테스트로 바꾸고 재현 테스트 8건(제외 4, 정책 용어 우선 3, 비슷한 말 1)을 추가해 수정 전 실패·수정 후 통과를 확인. 실제 수집 제목 60건의 판정은 수정 전후 변화 0건.
